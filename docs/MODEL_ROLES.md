# 模型与工具职责

## 当前正式职责

| 参与者 | 职责 | 权限边界 |
|---|---|---|
| Codex | 主创、工作流控制、证据核对、意见综合、修改执行、归档 | 不绕过人工发布闸门；不盲从无证据意见 |
| Claude | 独立视觉方向、构图、叙事节奏、字幕与画面质量评审 | 必须获得完整时间线证据；不单独批准发布 |
| MiniMax M3 | 独立完整视频、运动、声音、文案、事实清晰度及发布风险评审 | 正式视频评审必须接收完整视频；不单独批准发布 |
| MiniMax H3 | 图片转视频、首尾帧视频等生成后端 | 是生成器，不是评审者；输出必须重新进入评审循环 |
| ComfyUI | 本地模型和工作流执行平台 | 不作创意裁决；只运行已注册并验证的API工作流 |
| FFmpeg | 剪辑、字幕合成、转码和技术分析 | 不作内容决定 |
| 所有者 | 方向、真实冲突、事实/隐私不确定和最终发布裁决 | 普通、低风险修改不要求逐项确认 |

## 已退出正式路线

DeepSeek曾参与早期文案评审和首个归档包，因此历史文件中仍会出现DeepSeek记录。自2026-08-11起，它不再是正式生产评审者；当前正式双评审者为Claude与MiniMax M3。

## 完整证据原则

- 视频阶段：MiniMax M3接收完整视频；Claude接收覆盖完整时长的一秒一帧时间线、字幕边界帧、封面和必要的源素材证据。
- 图片阶段：两位评审者接收全部候选图片、文字、用途与平台裁切预览。
- 策划阶段：两位评审者接收完整brief、素材清单、约束、候选方案和选择理由。
- 发布包阶段：两位评审者接收最终媒体、全部封面、完整发布文案和平台变体。
- 若某模型的接口不能实际接收所需证据，必须将该评审标为“证据不足”，不得伪装成完整评审。
