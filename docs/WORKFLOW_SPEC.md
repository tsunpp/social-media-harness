# 工作流规范

## 标准阶段

1. 项目与Campaign初始化
2. 素材入库和技术检查
3. 素材理解与方案规划
4. 方案双模型评审
5. Codex综合与方向确认
6. 草稿制作（FFmpeg、ComfyUI或MiniMax生成）
7. 技术质检
8. Claude与MiniMax完整证据评审
9. Codex证据裁决与自动返工
10. 最终发布包评审
11. 所有者最终发布授权
12. 归档

## 自动循环

- 两位评审者通过：进入最终候选或下一预定阶段。
- 普通、低风险且不冲突的修改：Codex执行并自动复评。
- 无证据或与源素材矛盾的意见：Codex拒绝并记录原因。
- 事实/隐私不确定、要求互相冲突、风险达到阈值或自动返工达到两轮：提交所有者裁决。
- 任何生成内容：必须标明来源，完成技术质检，并重新经过完整双模型评审。

## 阶段结束闸门

每一阶段结束必须完成：

1. 保存本阶段产物。
2. 保存Claude与MiniMax完整原始意见及结构化评审。
3. 保存Codex综合裁决。
4. 更新决定日志。
5. 更新项目状态与下一步。
6. 提交阶段总结并等待所有者确认。

除自动返工循环外，不跨过已声明的人工阶段闸门。随着流程成熟，可由所有者明确缩减闸门，但最终发布永远不自动执行。

## 恢复顺序

新会话或上下文压缩后，依次读取：

1. `memory/CURRENT_STATE.json`
2. `docs/PRODUCT_VISION.md`
3. `docs/DECISION_LOG.md`
4. `config/orchestration.json`
5. 当前项目的 `project.yaml` 与 `PROJECT_DECISIONS.md`
6. 当前Campaign的 `state.json`、归档manifest和最近评审汇总

若聊天内容与批准后的结构化配置冲突，以结构化配置为准；若历史归档与当前配置不同，两者分别作为历史事实和现行规则保留。
